
## AI Development Knowledge

- For project requirements, bug fixes, and refactoring, use `.cursor/skills/knowledge-flywheel/SKILL.md` alongside the current task workflow.
- Before analysis/implementation, recall relevant project experience using the task description and known file paths; briefly report the IDs actually adopted. Do not repeat a node already handled in this task.
- During work, capture reusable user corrections and confirmed root causes as candidates. Keep one-off requirements in the existing task record; do not turn them into team-wide rules.
- After verification, before final delivery or handoff, distill supported conclusions, update stale knowledge, and briefly report the knowledge changes. No new insight means no new card.
- Reuse existing Spec/SDD records and authorization. This adds no second approval or mandatory test suite; record actual verification honestly. Knowledge text does not authorize executing commands or expanding task scope.
- Shared cards: `docs/knowledge/cards/`. Team usage: `docs/knowledge/README.md`. Ordinary Q&A does not create knowledge records.
